# 资料管理：文件夹上传与云盘式目录管理 — 用户故事

> 编号说明：US-001 ~ US-014 与 PM 草稿 US-1 ~ US-14 一一对应（US-N = US-0NN）；US-015 ~ US-017 为补齐需求覆盖新增。基线 `docs/user_stories.md`（US-IB-01 ~ US-IB-54）只读，本文不修改。

## 用户故事

### US-001: 上传整个文件夹并保留子目录结构
- 故事：As a 管理者, I want to 选择一个本地文件夹并整体上传, so that 整个文件夹及其子目录结构在资料库中原样保留，不必逐个文件上传。
- 关联需求：REQ-FUNC-001（另涉 REQ-FUNC-010、REQ-NFUNC-005）；优先级：Must Have；故事点：8 [ESTIMATE]；来源：用户原文 / PM 草稿 US-1；空子文件夹：用户确认 CL-008（OQ-08）；内部文件全部被跳过的子文件夹不创建（AC-001-04 引申解释）：用户确认 CL-009
- AC-001-01：Given 管理者位于资料库某目录且选择了本地文件夹 `A`（含子文件夹 `A/B`，其中 `A/x.pdf`、`A/B/y.txt` 均合规）/ When 确认上传 / Then 当前目录下出现文件夹 `A`，`A` 内含文件 `x.pdf` 与子文件夹 `B`，`B` 内含 `y.txt`；两个文件的层级路径与本地一致。
- AC-001-02：Given 同上，且文件夹 `A` 内含不合规文件 `bad.exe`（不支持类型）/ When 确认上传 / Then 合规文件正常入库，`bad.exe` 不入库且列入结果汇总的"跳过"列表（见 US-002）；`A` 的目录结构中不出现 `bad.exe`。
- AC-001-03：Given 无管理权限的项目成员 / When 尝试上传文件夹（含直接调用接口）/ Then 返回 403，资料库中不产生任何目录或文件，页面上不展示可用的"上传文件夹"入口或点击后提示"无管理权限"。
- AC-001-04：Given 本地文件夹 `A` 含合规文件 `A/x.pdf`、一个不含任何文件的子文件夹 `A/empty`、以及一个仅含不支持类型文件 `A/onlybad/z.exe` 的子文件夹 `A/onlybad` / When 确认上传 / Then 资料库中只创建 `A`（内含 `x.pdf`）；`A/empty` 与 `A/onlybad` 均不创建（资料库内 `A` 下的子文件夹数为 0）；`z.exe` 列入汇总的"跳过"列表。

### US-002: 文件夹上传的整体进度与结果汇总
- 故事：As a 管理者, I want to 在文件夹上传时看到整体进度，并在结束后看到成功/跳过/失败数量及原因, so that 我能确认哪些文件没进库并据此处理。
- 关联需求：REQ-FUNC-002（另涉 REQ-NFUNC-007）；优先级：Must Have；故事点：5 [ESTIMATE]；来源：PM 草稿 US-2，用户确认 CL-002；不支持类型跳过：用户答复 CL-005；归类口径：用户答复 CL-008
- AC-002-01：Given 上传一个含 100 个文件的文件夹 / When 上传进行中 / Then 页面显示"已处理 N / 100"并随处理推进递增，N 单调不减，结束时 N = 100。
- AC-002-02：Given 该文件夹含 95 个合规文件、3 个不支持类型文件、1 个空文件、1 个超过 50MB 的文件 / When 上传结束 / Then 汇总显示"成功 95、跳过 5、失败 0"（三数之和 = 100）；列出 5 个被跳过文件的相对路径与原因（如"不支持的文件类型 .exe"、"文件为空"、"文件超出大小上限（50MB）"）；魔数校验失败的文件（如扩展名为 `.pdf` 但内容不是 PDF）同样计入"跳过"，原因为"文件内容与扩展名不符"；"失败"只用于服务端处理错误（见 AC-002-03）。
- AC-002-03：Given 上传过程中有一个文件处理失败（服务端临时错误，如服务暂时不可用）/ When 上传继续 / Then 其余文件不受影响继续完成，已成功的文件保持可用；该文件计入"失败"并出现在汇总的失败列表中，页面不整体报错中断。

### US-003: 云盘式目录浏览
- 故事：As a 项目成员, I want to 像云盘一样进入文件夹、通过面包屑跳转、返回上级, so that 我能在多层目录中快速找到资料。
- 关联需求：REQ-FUNC-003；优先级：Must Have；故事点：5 [ESTIMATE]；来源：用户原文 / PM 草稿 US-3；浏览权限：用户确认 CL-008（OQ-07）；跨项目 404：用户答复 CL-010（A-10）
- AC-003-01：Given 一名已认证的本项目成员（不要求具备管理权限），根目录下有文件夹 `A`，`A` 下有子文件夹 `B` / When 依次点击进入 `A`、`B` / Then 页面分别只显示该目录直接包含的文件夹与文件；面包屑依次显示"根 > A"、"根 > A > B"；点击面包屑中的"A"回到 `A` 的内容；点击"返回上级"从 `B` 回到 `A`。
- AC-003-02：Given 某目录下有 150 个条目 / When 浏览该目录 / Then 条目按分页呈现，每页不超过 100 条，且可翻页看到全部 150 条、无重复无遗漏；同一目录多次刷新排序一致（文件夹在前，其后按名称升序）。
- AC-003-03：Given 项目 P1 的成员，项目 P2 中有目录 `X`（id 为 `x1`）/ When 以 P1 的身份按目录 id `x1` 请求 P2 的目录 / Then 返回 404，响应与请求一个不存在的目录 id 完全不可区分，不泄露 P2 的任何目录或文件名；若请求项目头与令牌所属项目不一致（归属断言失败），则仍返回 403。（用户答复 CL-010）

### US-004: 新建文件夹
- 故事：As a 管理者, I want to 在当前目录新建文件夹, so that 我能按主题组织资料。
- 关联需求：REQ-FUNC-004、REQ-FUNC-015、REQ-FUNC-016（名称校验）；优先级：Must Have；故事点：2 [ESTIMATE]；来源：用户原文 / PM 草稿 US-4
- AC-004-01：Given 管理者位于目录 `D` 且 `D` 下无同名文件夹 / When 输入名称 `设计` 并确认 / Then `D` 下立即出现文件夹 `设计`（空），且刷新页面后仍存在。
- AC-004-02：Given `D` 下已有文件夹 `设计` / When 再次新建同名 `设计` / Then 拒绝创建并提示"同名文件夹已存在"，`D` 下仍只有一个 `设计`。
- AC-004-03：Given 当前目录已处于第 10 层（根目录下一级文件夹为第 1 层）/ When 在其中新建文件夹 / Then 拒绝并提示"目录层级已达上限（10 层）"。

### US-005: 重命名文件夹
- 故事：As a 管理者, I want to 重命名文件夹, so that 目录名称能随资料整理而调整。
- 关联需求：REQ-FUNC-005（另涉 REQ-NFUNC-001）；优先级：Must Have；故事点：3 [ESTIMATE]；来源：用户原文 / PM 草稿 US-5
- AC-005-01：Given 文件夹 `旧名` 内有 3 个已索引文件 / When 重命名为 `新名` / Then 列表显示 `新名`，其内 3 个文件仍在其中且状态仍为"已索引"；问答引用这些文件时，目录路径显示 `新名/…`，不再出现 `旧名`。
- AC-005-02：Given 同级已存在名为 `新名` 的文件夹 / When 将另一文件夹重命名为 `新名` / Then 拒绝并提示"同名文件夹已存在"，原名称保持不变。
- AC-005-03：Given 项目成员无管理权限 / When 尝试重命名 / Then 返回 403，名称不变。

### US-006: 删除文件夹（二次确认、递归、清除向量）
- 故事：As a 管理者, I want to 删除一个文件夹并连同其内全部内容一起清除, so that 过期资料不再占用资料库，也不会再被问答检索到。
- 关联需求：REQ-FUNC-006（另涉 REQ-NFUNC-001、REQ-NFUNC-007）；优先级：Must Have；故事点：8 [ESTIMATE]；来源：用户原文 / PM 草稿 US-6
- AC-006-01：Given 文件夹 `A` 含 2 个子文件夹与 10 个文件 / When 点击删除 / Then 弹出确认框，显示"将删除 2 个子文件夹、10 个文件"；点击取消后 `A` 及内容均保持不变。
- AC-006-02：Given 已在确认框中确认删除 / When 删除完成 / Then `A` 及其下全部文件与子文件夹从列表消失；这 10 个文件各自的向量在向量库中数量为 0；用其中任一文件独有关键词发起问答检索，命中该文件内容的条数为 0。
- AC-006-03：Given 删除过程中有 1 个文件的向量清理失败（如向量库暂时不可用）/ When 删除结束 / Then 页面提示"部分删除失败：1 个文件"并列出该文件；该文件及其所在的文件夹路径仍可见（可再次删除），不出现"列表看不到但仍能检索到"的文件。
- AC-006-04：Given 文件夹内某文件正处于"处理中"（索引中）/ When 确认删除 / Then 删除成功，该文件最终不在列表也不在向量库中（后台任务安全退出，不因删除而崩溃或重新写入向量）。

### US-007: 上传单个/多个文件到指定文件夹
- 故事：As a 管理者, I want to 选择一个或多个文件并上传到当前所在的文件夹, so that 新资料直接归档到正确位置。
- 关联需求：REQ-FUNC-007（另涉 REQ-FUNC-010）；优先级：Must Have；故事点：3 [ESTIMATE]；来源：PM 草稿 US-7，用户确认 CL-002
- AC-007-01：Given 管理者位于目录 `D` / When 一次选择 3 个合规文件并上传 / Then `D` 下出现这 3 个文件，各自初始状态为"待处理"并随后转为"已索引"或"失败"；根目录下不出现它们。
- AC-007-02：Given 选择的文件中有 1 个不支持类型 / When 上传 / Then 另外合规文件正常入库，不支持者给出"不支持的文件类型"提示且不入库；未选任何文件时"上传"按钮不可用。

### US-008: 更新文件并自动重新索引
- 故事：As a 管理者, I want to 用新版本替换已有文件, so that 资料保持最新且检索只命中最新内容。
- 关联需求：REQ-FUNC-008、REQ-NFUNC-002、REQ-NFUNC-001、REQ-NFUNC-004；优先级：Must Have；故事点：8 [ESTIMATE]；来源：用户原文 / PM 草稿 US-8；不保留历史：用户答复 CL-004；失败保留旧版、格式变化、内容相同：用户确认 CL-008（OQ-01、OQ-09）；更新后显示新文件名及重名冲突：用户确认 CL-009（OQ-13）；重名冲突各选项语义：用户答复 CL-010（A-02）
- AC-008-01：Given 文件 `规范.pdf` 已索引，其旧版独有关键词 K1，新版独有关键词 K2 / When 管理者更新为新版并等待索引完成 / Then 该文件状态为"已索引"，"最近更新时间"为本次更新时间；检索 K2 命中该文件，检索 K1 命中该文件的条数为 0；该文件在列表中仅有一条记录，所在目录与名称不变。
- AC-008-02：Given 更新已提交但新版尚未索引完成 / When 此时检索 K1 / Then 仍可命中旧版内容（OQ-01 已确认：新版索引成功前旧版继续可检索）；新版索引成功后 K1 不再命中。
- AC-008-03：Given 新版文件解析失败 / When 索引结束 / Then 状态显示"更新失败"及失败原因，旧版内容保持可检索，页面不得显示为"已索引（新版）"；可对该文件重试。
- AC-008-04：Given 无管理权限的项目成员 / When 尝试更新文件 / Then 返回 403，文件内容、状态与向量均不变；且不存在"保留历史版本"的入口（CL-004）。
- AC-008-05：Given 已索引的文件 `规范.pdf`（旧版独有关键词 K1）/ When 管理者用不同格式的新文件 `规范v2.docx`（独有关键词 K2）更新并等待索引完成 / Then 更新被接受，不以"格式与原文件不一致"为由拒绝；该文件仍为同一条记录，条目显示名称变为新文件名 `规范v2.docx`（含新扩展名，不再显示 `规范.pdf`），所在目录与上传时间不变，状态为"已索引"，检索 K2 命中该文件、检索 K1 命中该文件的条数为 0。
- AC-008-06：Given 已索引的文件 F，记其状态"已索引"、索引成功时间 T2、最近更新时间 TU、向量数 N / When 管理者用与 F 现有内容字节完全相同的文件更新 / Then 页面提示"内容未变化"，不触发重新索引：F 的状态仍为"已索引"，索引成功时间仍为 T2，最近更新时间仍为 TU，向量数仍为 N。
- AC-008-07：Given 目录 `D` 下已有已索引文件 `规范.pdf` 与另一文件 `规范v2.docx` / When 管理者用文件 `规范V2.DOCX`（与 `规范v2.docx` 仅大小写不同）更新 `规范.pdf` / Then 弹出同名冲突对话框，列出冲突条目 `规范v2.docx` 并提供"覆盖 / 跳过 / 两者都保留并自动改名"三选项（同 AC-011-01）；用户选择前 `D` 中两个条目的名称、内容、状态、向量均不变；关闭对话框而未选择、或选"跳过"，均视为取消本次更新，`规范.pdf` 保持原名与原内容，`规范v2.docx` 不变；选"覆盖"时，以 `规范V2.DOCX` 的内容更新 `规范v2.docx`（按更新处理，重新索引，仍为同一条记录），`规范.pdf` 保持原名、原内容与原状态不变，`D` 下条目数不变；选"两者都保留并自动改名"时，`规范.pdf` 更新后显示名为 `规范V2 (2).docx`，`规范v2.docx` 不变，`D` 下无同名（不区分大小写）条目。（用户答复 CL-010）

### US-009: 查看文件的上传时间、更新时间、索引成功时间与索引状态
- 故事：As a 项目成员, I want to 在每个文件上看到上传时间、最近更新时间、索引成功时间和索引状态, so that 我能判断资料是否已可被检索、是否是最新。
- 关联需求：REQ-FUNC-009、REQ-NFUNC-003、REQ-NFUNC-004；优先级：Must Have；故事点：5 [ESTIMATE]；来源：用户原文 / PM 草稿 US-9；重建刷新与时区：用户确认 CL-008（OQ-06、OQ-10）
- AC-009-01：Given 文件 F 于 T1 上传、索引成功于 T2（T2 ≥ T1）、从未更新 / When 查看列表 / Then F 显示上传时间 T1、最近更新时间"—"、索引成功时间 T2、状态"已索引"，时间均为 `YYYY-MM-DD HH:mm:ss`，按浏览器本地时区显示。
- AC-009-02：Given F 于 T3 被更新，新版索引成功于 T4 / When 查看列表 / Then 上传时间仍为 T1，最近更新时间为 T3，索引成功时间为 T4；对 F 仅做重命名或移动后，三个时间均不变。
- AC-009-03：Given 文件 G 索引失败 / When 查看列表 / Then G 的状态显示"失败"并展示失败原因，索引成功时间显示"—"（若 G 此前有过成功索引的旧版，则不得把旧时间当作新版的索引成功时间）；处理中的文件状态显示"处理中"，索引成功时间为"—"。
- AC-009-04：Given 文件 F 于 T1 上传、索引成功于 T2、最近更新时间为"—" / When embedding 模型变更后执行索引重建，F 重新索引完成于 T5 / Then F 的索引成功时间显示 T5（不再是 T2），上传时间仍为 T1，最近更新时间仍为"—"，状态为"已索引"，F 所在的目录位置不变。

### US-010: 所有上传内容可被向量检索
- 故事：As a 问答用户, I want to 通过知识问答检索到文件夹上传、目录内上传及更新后的全部资料, so that 上传即可用。
- 关联需求：REQ-FUNC-010、REQ-NFUNC-005；优先级：Must Have；故事点：5 [ESTIMATE]；来源：用户原文 / PM 草稿 US-10
- AC-010-01：Given 通过文件夹上传入库的文件 F（位于 `A/B/`）已显示"已索引" / When 在同一项目中就 F 独有内容发起问答 / Then 回答的引用来源包含 F，chunk 数 > 0。
- AC-010-02：Given 项目 P2 的问答用户 / When 检索项目 P1 中文件夹内文件的独有内容 / Then 引用来源中不出现该文件，P1 的内容不泄露。
- AC-010-03：Given 文件夹上传中某文件索引失败 / When 检索其内容 / Then 无命中，且该文件在列表中状态为"失败"（不是"已索引"）。

### US-011: 上传遇到同名文件/文件夹时的明确处理
- 故事：As a 管理者, I want to 在上传遇到同名文件或文件夹时选择"覆盖 / 跳过 / 两者都保留并自动改名", so that 不会在无意中覆盖或重复。
- 关联需求：REQ-FUNC-011（另涉 REQ-FUNC-008、REQ-FUNC-016）；优先级：Must Have；故事点：8 [ESTIMATE]；来源：用户答复 CL-003；PM 草稿 US-11，用户确认 CL-002；大小写、合并、改名格式：用户确认 CL-008（OQ-02、OQ-03、OQ-10）
- AC-011-01：Given 目录 `D` 已有 `a.pdf` / When 上传另一个 `a.pdf` 到 `D` / Then 弹出对话框列出冲突文件 `a.pdf` 并提供"覆盖 / 跳过 / 两者都保留并自动改名"三选项；在用户选择前 `D` 中的 `a.pdf` 内容、状态、向量均不变。
- AC-011-02：Given 对话框中选"覆盖" / When 确认 / Then 按"更新"处理（行为同 US-008：旧向量移除、重新索引、列表中仍只有一个 `a.pdf`）；选"跳过" → 原文件不变，新文件不入库并列入汇总的"跳过"；选"两者都保留" → 新文件以自动改名 `a (2).pdf` 入库（若 `a (2).pdf` 已存在则为 `a (3).pdf`，依次顺延），原 `a.pdf` 不变，两者各自独立可检索。
- AC-011-03：Given 上传文件夹 `A`，目标目录已有同名文件夹 `A`，且其中 `A/x.pdf` 同名冲突 / When 用户对文件夹选"覆盖"、对 `x.pdf` 冲突按提示确认 / Then 两个 `A` 合并为一个；`x.pdf` 按更新处理；原 `A` 中未重传的其他文件保持不变。
- AC-011-04：Given 对话框已弹出 / When 用户关闭对话框而未选择 / Then 视为取消整次上传，资料库无任何变化。
- AC-011-05：Given 目录 `D` 已有文件 `A.pdf` / When 上传名为 `a.pdf`（仅大小写不同）的文件到 `D` / Then 同样弹出同名冲突对话框，列出冲突文件；选"两者都保留并自动改名"时，新文件以 `a (2).pdf` 入库，`A.pdf` 不变；选择前 `D` 中不出现 `a.pdf` 条目。

### US-012: 重命名文件
- 故事：As a 管理者, I want to 重命名文件, so that 文件名能准确反映内容。
- 关联需求：REQ-FUNC-012；优先级：Should Have；故事点：2 [ESTIMATE]；来源：PM 草稿 US-12，用户确认 CL-002；扩展名限制：用户答复 CL-010（A-04）
- AC-012-01：Given 已索引文件 `旧.pdf` / When 重命名为 `新.pdf` / Then 列表显示 `新.pdf`，状态仍为"已索引"，三个时间不变；问答引用该文件时显示 `新.pdf`，不再显示 `旧.pdf`。
- AC-012-02：Given 同目录已有 `新.pdf` / When 将 `旧.pdf` 重命名为 `新.pdf` / Then 拒绝并提示"同名文件已存在"，名称不变；若新名称改变了扩展名（无论改为不支持类型还是另一受支持类型，如 `旧.pdf` → `旧.docx`），则同样拒绝并提示"如需更换格式请使用更新文件"，名称不变。（用户答复 CL-010）

### US-013: 移动文件/文件夹到其他目录
- 故事：As a 管理者, I want to 把文件或文件夹移动到同项目的其他目录, so that 我能随时重新整理资料结构。
- 关联需求：REQ-FUNC-013（另涉 REQ-FUNC-011、REQ-FUNC-015、REQ-NFUNC-001）；优先级：Should Have；故事点：8 [ESTIMATE]；来源：PM 草稿 US-13，用户确认 CL-002
- AC-013-01：Given 文件 `x.pdf` 位于 `A/`，目标目录 `B/` 无同名 / When 将 `x.pdf` 移到 `B/` / Then `A/` 中不再有 `x.pdf`，`B/` 中有且状态仍为"已索引"，仍可被检索（命中数不变），问答引用路径显示 `B/x.pdf`。
- AC-013-02：Given 文件夹 `A` 含 5 个文件 / When 将 `A` 移到 `C/` / Then `A` 及其 5 个文件整体出现在 `C/` 下，原位置不再有；这 5 个文件检索能力不变。
- AC-013-03：Given 目标目录有同名文件/文件夹 / When 移动 / Then 弹出与 US-011 相同的"覆盖 / 跳过 / 两者都保留并自动改名"选择。
- AC-013-04：Given 将文件夹 `A` 移动到其自身或其子孙目录，或移动后层级将超过 10 层（按从根起算的绝对层数，根目录下一级文件夹为第 1 层，与 AC-004-03、AC-015-02 一致），或目标属于其他项目 / When 移动 / Then 拒绝，分别提示"不能移动到自身或其子目录"、"目录层级已达上限（10 层）"、"不支持跨项目移动"，原结构不变。

### US-014: 问答引用来源显示文件所在目录路径
- 故事：As a 问答用户, I want to 在问答引用来源中看到文件所在的目录路径, so that 我能区分同名文件并知道资料出处。
- 关联需求：REQ-FUNC-014；优先级：Could Have；故事点：3 [ESTIMATE]；来源：PM 草稿 US-14，用户确认 CL-002
- AC-014-01：Given 文件位于 `技术文档/设计/方案.pdf` 且被问答命中 / When 查看引用来源 / Then 引用来源显示 `技术文档/设计/方案.pdf`（含目录路径与文件名）。
- AC-014-02：Given 位于根目录的文件被命中 / When 查看引用来源 / Then 仅显示文件名（路径为根，不显示空的前缀或多余的 `/`）；文件被移动或所在文件夹被重命名后再次问答，显示的是新路径。

### US-015: 文件夹上传的层级、数量与总大小上限
- 故事：As a 管理者, I want to 在超过层级、文件数或总大小上限时被明确拦截并得到提示, so that 一次误操作不会把过量内容压进资料库。
- 关联需求：REQ-FUNC-015（另涉 C-01、C-02）；优先级：Must Have；故事点：3 [ESTIMATE]；来源：用户答复 CL-006；绝对层数与总大小上限：用户确认 CL-008（OQ-04、OQ-05）
- AC-015-01：Given 默认配置（最多 10 层、单次 1000 个文件）/ When 选择含 1001 个文件的文件夹上传 / Then 在上传开始前整体拒绝，提示"单次最多上传 1000 个文件（当前 1001）"，资料库中不产生任何新目录或文件。
- AC-015-02：Given 管理者当前位于资料库第 8 层目录（从根起算，根目录下一级文件夹为第 1 层），所选本地文件夹自身及其子目录共嵌套 3 层（如 `A/B/C`）/ When 确认上传 / Then 上传后最深将处于第 11 层，在上传开始前整体拒绝，提示"目录层级最多 10 层"，并不产生半成品；同一文件夹若从第 7 层目录上传（最深第 10 层）则通过层级校验。
- AC-015-03：Given 管理者将上限配置为 20 层 / 2000 个文件后 / When 上传含 1500 个文件、15 层的文件夹 / Then 通过限制校验正常开始上传（验证数值可配置，且单个文件的 50MB 上限仍适用）。
- AC-015-04：Given "单次上传总大小"上限配置为 L（默认值由架构阶段评估 C-02 后给出，验收时以实际配置值为准），所选文件夹文件数与层级均未超限 / When 所选文件总大小超过 L 并确认上传 / Then 在上传开始前整体拒绝，提示"单次上传总大小超过上限（当前 {实际大小}，上限 {L}）"，资料库中不产生任何新目录或文件；总大小恰为 L 时通过该项校验。

### US-016: 文件夹与文件名称校验
- 故事：As a 管理者, I want to 在新建、重命名时得到明确的名称校验提示, so that 目录里不会出现无法识别或不合法的名称。
- 关联需求：REQ-FUNC-016（原 `[INFERRED]`，已由用户确认 CL-008）；优先级：Should Have；故事点：2 [ESTIMATE]；来源：用户确认 CL-008（名称规则、同名不区分大小写）
- AC-016-01：Given 新建文件夹对话框 / When 输入空白、含 `/` 或 `\`、或超过 255 个字符的名称 / Then 拒绝创建并分别提示"名称不能为空"、"名称不能包含 / 或 \"、"名称不能超过 255 个字符"，不创建任何条目。
- AC-016-02：Given 重命名文件夹或文件 / When 输入合法名称（如 `2026 规范 v2`）/ Then 重命名成功；输入非法名称时与新建一致被拒绝且原名保持不变。
- AC-016-03：Given 目录 `D` 下已有文件夹 `Design` / When 新建名为 `design` 的文件夹，或将 `D` 下另一文件夹重命名为 `DESIGN` / Then 均被拒绝并提示"同名文件夹已存在"，`D` 下文件夹数量不变，被重命名的文件夹名称保持不变。

### US-017: 既有平铺文件在上线后归入根目录
