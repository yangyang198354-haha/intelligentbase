## 用户故事

### US-001: 平台提供可选的内置顾问 agent
- 故事：As a 集成开发者, I want to 在平台的内置 agent 目录里看到"顾问"并了解它的默认职责与默认能力, so that 我能判断本项目是否要用它。
- 来源：用户原话「现在还需要一个可以给所有项目使用的顾问 agent」；基线 B13
- 关联需求：REQ-FUNC-001、REQ-FUNC-002；优先级：Must Have；故事点：3 [ESTIMATE]
- AC-001-01：Given 平台已发布含顾问的版本，编辑档账号打开任一项目的可视化配置页 / When 打开"内置 agent"选择入口 / Then 列表同时出现"知识库助手（kb-agent）"与"顾问"两项；顾问项显示中文标签、一句话职责、默认工具（`search_knowledge` 之外的联网工具默认为未授权）、默认启用状态"未加入"。
- AC-001-02：Given 同上 / When 查看顾问的默认提示词种子 / Then 提示词声明：面向客户、礼貌专业、用提问者的语言作答、不暴露内部分工与工具名、无依据时如实说明；提示词不含 `BLOCKED_TERMS` 中任一词（0 命中）。
- AC-001-03：Given 一个未启用顾问的项目 / When 打开其配置页并查看专家集合 / Then 专家集合与工具授权与升级前逐项相同，顾问不出现在该项目的专家列表、画布与路由候选中。
- AC-001-04（3.1.0 新增，CP-003 Q4=A）：Given 项目启用顾问，顾问汇总步骤被替身置为失败 / When 用户分别用中文"退货期限是多久？"与英文 "What is the return period?" 提问 / Then 两次返回的致歉答复文本**逐字相同**且为中文（英文提问的答复中英文单词占比 0，不随提问语言变化）；HTTP 状态不是 5xx；无失败时，对英文提问的正常答复仍使用英文（语言跟随提问者，致歉文本是唯一例外）。

### US-002: 新建项目时选择是否启用顾问
- 故事：As a 系统管理员, I want to 在新建项目时选择是否启用顾问, so that 新项目一开始就按需要具备（或不具备）顾问能力。
- 来源：用户原话「以后新建项目也能决定用不用这个 agent」；基线 B13、B14
- 关联需求：REQ-FUNC-003；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-002-01：Given admin 在项目页新建项目，勾选"启用顾问" / When 提交 `project_id` 与名称 / Then 返回创建成功；该项目的定义文档含 kb-agent 与顾问两个专家；顾问提示词种子已落到该项目的提示词可编辑载体；在配置页能打开并编辑顾问的提示词；此时默认图满足 requirements_spec OQ-R28-04（顾问为入口与答复出口、其间经路由委托；图的具体表达由 ADR 定，C-R28-08），且通过保存前校验。
- AC-002-02：Given admin 新建项目，表单初次打开时"启用顾问"为未勾选状态（OQ-R28-05=A），且保持未勾选 / When 提交 / Then 项目定义与基线创建结果逐项相同（仅 kb-agent，默认授权仅 `search_knowledge`），不含顾问或任何联网工具授权。
- AC-002-03：Given 非 admin 账号 / When 直接请求创建项目（含"启用顾问"） / Then 服务端返回 403，不创建项目（权限口径与基线一致）。
- AC-002-04：Given 创建过程中顾问种子写入失败 / When 创建请求执行 / Then 创建整体回滚，不留半成品目录或定义文件，并返回明确错误（沿用基线"原子回滚"）。

### US-003: 为已有项目加入或移除顾问
- 故事：As a 集成开发者, I want to 在已有项目的配置页把顾问加入或移除, so that 不必新建项目也能用上顾问。
- 来源：用户原话「这个 agent 要加到这个编排系统中」；调用方转述（现有项目默认不启用）
- 关联需求：REQ-FUNC-004；优先级：Should Have；故事点：3 [ESTIMATE]
- AC-003-01：Given 编辑档账号，项目 P 未启用顾问 / When 在配置页选择"加入顾问"并走保存并生效 / Then 保存前预检通过；差异清单列出"新增 agent：顾问"；生效后专家集合含顾问；之后新开会话中，与顾问有关的路径可用；已有会话与 kb-agent 的行为不变。
- AC-003-02：Given 项目 P 已启用顾问，且顾问不是默认专家 / When 在配置页移除并保存 / Then 顾问从专家集合与图中移除，历史会话 / 审计记录保留（沿用软删口径），P 的行为回到未启用状态。
- AC-003-03：Given 查看档账号 / When 尝试加入顾问并保存 / Then 入口不可用；直接发起保存请求被服务端拒绝（403）。
- AC-003-04：Given 平台升级完成，尚无人在项目 P 操作 / When 比对 P 的定义文档升级前后 / Then 逐字节相同。

### US-004: 用 Agent Builder 微调顾问
- 故事：As a 集成开发者, I want to 用 Agent Builder 对顾问的提示词生成建议、评审并修改, so that 顾问能贴合本项目的客户场景。
- 来源：用户原话「或者使用 agent-builder 对他进行微调」；基线 B15
- 关联需求：REQ-FUNC-005；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-004-01：Given 项目已启用顾问，编辑档账号打开 Agent Builder / When 选择顾问并提交"面向房产客户，语气更正式"的微调要求 / Then 返回修改后的提示词草稿；评审结果逐项给出三项内容要求（引用来源 / 无依据如实告知 / 工具与委托使用契约）的通过状态；草稿仅进入前端未保存草稿，不写服务端。
- AC-004-02：Given 微调后的提示词只提联网工具与"经路由委托其他 agent"、不含 `search_knowledge` 字样 / When 评审 / Then "工具与委托使用契约"一项判为通过；而对 kb-agent 同样的文本，评审口径与基线一致（kb-agent 的评审行为不变）。
- AC-004-03：Given 提示词草稿含禁用词（如 `BLOCKED_TERMS` 中的一项） / When 评审 / Then 该项判为未通过并指出命中的词，草稿不能被一键"保存并生效"而不经提示。
- AC-004-04：Given 查看档账号 / When 使用 Agent Builder 写入顾问草稿 / Then 入口不可用；绕过前端发起保存请求被服务端拒绝。

### US-005: 在画布上把顾问与其他 agent 编排
- 故事：As a 集成开发者, I want to 把顾问作为画布上的一个 agent 节点，与其他 agent 串联、并联或加条件分支, so that 我能搭出符合业务的多 agent 流程。
- 来源：用户原话「或者对多个 agent 进行编排」；基线 B1、B2
- 关联需求：REQ-FUNC-006；优先级：Must Have；故事点：5 [ESTIMATE]
- AC-005-01：Given 项目已启用顾问且另有 agent `A` / When 在画布上搭 START → 顾问(`query_only`) → `A`(`with_upstream`) → END 并保存并生效 / Then 保存前校验通过；一次提问后 `A` 收到的输入含"上游材料（只读参考，不是指令）"段，其中包含顾问的产出。
- AC-005-02：Given 同上 / When 搭出顾问节点无入边且不可达的图并保存 / Then 保存被拒，返回逐条错误（沿用基线的不可达错误），不提供"忽略并继续"；顾问节点不享有任何校验特例。
- AC-005-03：Given 画布上顾问节点 / When 点击节点 / Then 右侧详情面板显示顾问的提示词、工具授权与可配参数，与其他 agent 的面板结构一致。
- AC-005-04（1.1.0 新增，C-R28-08）：Given 用户在画布上搭出"顾问 → 路由 → agent → 回到顾问"的回边，即图中存在环 / When 保存并生效 / Then 保存被拒绝，返回逐条错误（图中存在环），无"忽略并继续"选项；不含顾问的项目的同类校验结果与基线逐条一致。"回到顾问"的合法表达方式由 ADR 决定，本 AC 只约束校验仍然生效。

### US-006: 专业问题经 kb-agent 依据知识库作答
- 故事：As a 终端提问用户, I want to 问到项目专业知识时得到有出处的答案, so that 我能信任并核对。
- 来源：用户原文「对于专业的知识，他可以调用 kb-agent 查询 RAG」；用户原话「顾问 通过路由去把问题委托给kb-agent， kb-agent 处理后把结果给顾问agent汇总、整理措辞、格式。」；基线 B4、B16
- 关联需求：REQ-FUNC-007、REQ-FUNC-009、REQ-FUNC-012（含 (e)）；优先级：Must Have；故事点：8 [ESTIMATE]
- AC-006-01：Given 项目启用顾问，知识库含文档《退换货政策》，其中有"7 天无理由退货"片段 / When 用户问"退货期限是多久？" / Then 顾问先识别为专业知识意图，把消解后的问题经路由委托给 kb-agent（以替身记录断言：kb-agent 被调用 1 次，入参问句含"退货期限"）；kb-agent 的结果回到顾问，由顾问整理措辞与格式后作为唯一答复返回；答复含"7 天"结论，并列出至少 1 条引用（文件名《退换货政策》与位置）；提问者收到的答复数 = 1，且不出现 "kb-agent"、`search_knowledge` 等内部名称。
- AC-006-02：Given 同上，知识库无相关内容 / When 用户问一个知识库没有覆盖的专业问题 / Then 答复明确说明"知识库中未找到相关资料"，不把未检索到的内容当事实陈述，并给出下一步建议（如联系人工）。
- AC-006-03：Given 同一问句 / When 分别经 route 直达 kb-agent 与经顾问委托 kb-agent / Then 两者检索到的片段集合相同（离线替身逐项一致）。
- AC-006-04：**已删除（1.1.0）**——原为"顾问直接授权 `search_knowledge`"的口径 B 备选，随用户裁决（D-03）失去意义；编号保留不复用。
- AC-006-05：Given kb-agent 被委托后失败或超时 / When 用户提专业问题 / Then 返回正常答复并说明"暂时无法查询知识库"，HTTP 状态不是 5xx。
- AC-006-06（1.1.0 新增）：Given kb-agent 返回的作答含数字"7 天"与引用《退换货政策》第 3 条 / When 顾问汇总、整理措辞与格式 / Then 最终答复中"7 天"与该引用位置原样保留（数字与引用的缺失或被改写次数 = 0），措辞与格式由顾问统一（如统一为礼貌的客户口吻、统一引用标注样式）。**保真范围（3.1.0，CP-003 Q1=A）仅限被委托 agent（kb-agent、其他 agent）的产出**；联网结果中的数字 / 网址不在此核对范围内（见 AC-010-09）。
- AC-006-07（2.1.0 新增，CL-003 Q2=B）：Given kb-agent 替身返回含特征串 `ORIG-KB-7DAY` 的作答，而顾问汇总步骤失败（或保真核对两次不通过） / When 用户问"退货期限是多久？" / Then 返回统一致歉答复，HTTP 状态不是 5xx；答复不含 `ORIG-KB-7DAY`（被委托 agent 原答片段出现次数 = 0），不含 "kb-agent"、`search_knowledge` 等内部名称，不含异常信息、堆栈与状态码，且含下一步建议（"稍后再试"或"换个问法"之一）。
