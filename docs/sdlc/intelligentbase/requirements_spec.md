# 需求规格说明（REV-27 增量）— 可视化配置：删除画布节点

**范围声明**：本文件只写 REV-27 的增量。基线是 REV-26 已批准的需求（归档于 `docs/sdlc/intelligentbase/archive/rev26/requirements_spec.md` 与 `user_stories.md`，2.0.0 APPROVED，只读，不改）；对 REV-26 条目的"继承 / 变更 / 取代"关系登记在§取代登记。REV-26 的 REQ-FUNC-001~023 与本文件的 REQ-FUNC-001~ **编号空间不同**；引用 REV-26 条目时一律写"R26 REQ-FUNC-NNN"。
**编号方案**：`REQ-FUNC-001~`、`REQ-NFUNC-001~`、`C-R27-NN`、`OOS-R27-NN`、`OQ-R27-NN`。用户故事见 `docs/sdlc/intelligentbase/user_stories.md`。

## 执行摘要

- **业务背景（用户原文，2026-10-31，经主会话转述）**：「在可视化配置页面，当我新增一个节点，比如agent，路由，分支等等尚未完整编辑，没有通过校验。只有一个放弃改动按钮放弃添加的所有东西。我需要一个能放弃或者说删除一个节点的功能。先整理需求和用户故事。确认后开始开发。」
- **规模**：REQ-FUNC 13 条（Must 10 / Should 3）；REQ-NFUNC 3 条（Must 3）；约束 C-R27 5 条；范围外 OOS-R27 6 条；开放问题 OQ-R27 10 条（均非阻塞，已给推荐项，需求与 AC 按推荐项书写）。
- **[INFERRED] 占比**：3 条 ÷ (13 + 3) = 3 / 16 = **18.75%**（上限 20%，画像 P5 `inferred_max`）。3 条为 REQ-FUNC-005（免确认例外）、REQ-FUNC-012（差异清单覆盖所有节点类型）、REQ-FUNC-013（单步撤销），全部列入§待确认推断项（INF-1~3）。故事点为相对估算 `[ESTIMATE]`，属格式字段，不计入推断占比（记忆 M-RA-008）。
- **优先级规则**：用户原话明确要求的能力（能删除一个尚未完整编辑、未通过校验的节点）→ Must Have；围绕它的安全与一致性（连带边、确认、agent 两种移除语义、结构节点保护、只读档、残留清理、校验口径）→ 按风险性质定 Must；键盘入口、差异清单覆盖、撤销 → Should。按此规则：Must 10 / Should 3（需求）。
- **核心结论（现状核实，详见§现有系统基线）**：R26 REQ-FUNC-011 已承诺画布上"新增 / 删除节点"，但代码中只有 agent 节点能被删除（且删的是 agent 定义，不是"仅从画布移除"），route / condition / join / confirm 没有任何删除入口，Delete 键只删边；因此新增了未完成节点的用户只能用"放弃改动"丢弃全部未保存内容。本轮是对 R26 REQ-FUNC-011 的缺口补齐加若干安全规则。
- **待用户裁决**：OQ-R27-01~10（见§开放问题），其中 OQ-R27-07（与 R26 OQ-R26-11=A 软删口径的关系）和 OQ-R27-02（agent 默认删除语义）建议优先确认；其余可沿用推荐项。
