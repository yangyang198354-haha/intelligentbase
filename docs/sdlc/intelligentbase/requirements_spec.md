## 执行摘要

- **业务背景（用户原文，逐字）**：「我现在要对agent 工具调用增加mcp 适配。要求对标mcp 的业务流程，增加，变更，删除，查询新工具。能做好安全控制和调用。 先分析需求和用户故事。也完成设计草案。」
- **来源说明**：用户原话只有上面一段。下列均为**调用方转述**（PM 与用户讨论方向的转述，不是用户原话、不是已批准方案）：对标 MCP 的发现 / 调用 / 变更通知流程；平台作为 MCP 客户端、管理员登记 Server、工具带命名空间前缀；重点安全点清单（项目隔离、提示注入、凭证、SSRF、stdio、副作用确认、schema 变更复审、超时熔断、审计、删除 Server 后的授权）。MCP 协议事实取自官方规范网页，标 `[WEB: …]`，**仅作背景，不单独构成需求来源**。
- **规模（1.1.0）**：有效 REQ-FUNC **22** 条（Must 20 / Should 2 / Could 0；编号 001~024，其中 009、022 已移出本轮、保留为占位、不计数）；REQ-NFUNC 13 条（Must 12 / Should 1）；约束 C-R29 10 条；范围外 OOS-R29 **12** 条（新增 11、12）；开放问题 OQ-R29 14 条 + 架构开放问题 OQ-ARCH-R29 10 条，**已全部按推荐关闭**（CP-001），剩余未决 0 条，仅余若干"部署前 / 开发前人工核实项"（见§开放问题末尾，非阻断）。
- **[INFERRED] 占比（1.1.0）**：0 条 ÷ (22 + 13) = 0 / 35 = **0%**（上限 20%，画像 P5 `inferred_max`）。原 REQ-NFUNC-006、007、011 的 [INFERRED] 已由用户在 CP-001 Q3=A 确认默认数值，去标。度量中的验收样本量（注入集 N≥20、地址拒绝集 N≥30、canary 会话 N≥30）沿用 R28 已确认口径，不计推断；故事点为相对估算 `[ESTIMATE]`，属格式字段，不计入推断占比（记忆 M-RA-008）。
- **2.1.0 定向修订（REV-29 CP-002 用户裁决，经主会话转述，2026-11-06，用户原话："全部按推荐"）**：Q2=A（以 ADR-R29-11 为准，描述走净化截断、返回内容走围栏，REQ-NFUNC-003 / AC-027-01）、Q3=A（无独立终端提问用户主体，改匿名 401 / view·edit 档 403 口径，REQ-NFUNC-013 及 AC-001-03 / 003-03 / 011-03 / 016-05 / 025-04 / 026-03）、Q4=A（仅记录，见§开放问题"CP-002 决策记录"）。**计数不变**：有效 REQ-FUNC 22、REQ-NFUNC 13、[INFERRED] 0 ÷ 35 = 0%。
- **用户裁决（CP-001，经主会话转述，用户原话："全部按照推荐"）**：Q1=B（修订 DR-19，仅放开经登记 MCP Server 发现并审核的外部工具）、Q2=A（OQ-R29-02~14 按推荐：stdio 与 HITL 本轮不做）、Q3=A（INF-1~3 默认数值接受）、Q4=A（OQ-ARCH-R29-01~10 按推荐）、Q5=A（凭证加密存台账、主密钥由运维写入部署环境文件）。
- **优先级规则（说明一次）**：用户原话明确提到的能力（MCP 适配、对标 MCP 流程、工具的增 / 变 / 删 / 查、安全控制、调用）→ Must Have；用户未提、但为落地所必需的安全 / 兼容 / 降级 / 管理入口 → 按风险定 Must 或 Should。本机子进程（stdio）与调用前人工确认（HITL）经 CP-001 Q2=A 移入超出范围。用户未提的扩展（平台自身作为 MCP Server、resources / prompts / sampling 等非工具能力）一律放"超出范围"。
- **核心结论（现状核实，详见§现有系统基线）**：(1) 工具本体现在只能经代码在装配期登记，配置侧只能对既有工具做授权勾选与调参——这是用户历史裁决（DR-19 / OQ-IB-19），本需求**修订这一口径**（范围限于经登记 MCP Server 发现并审核的外部工具），已由用户裁决（CP-001 Q1=B，2026-11-05，见 C-R29-01）；(2) 现有"每 agent 授权 + 构造期 scope 绑定 + 平台限制类参数 LLM 不可见 + 联网工具的出网 / 预算 / 内容围栏治理"可作为 MCP 外部工具的行为先例；(3) 注册表"同名覆盖"语义对外部工具是遮蔽风险，必须有防护需求（REQ-FUNC-010）；(4) 系统没有"工具调用级"的人工确认，只有图节点级的 confirm 节点（B13）；(5) 工具授权被保存校验按"工具必须存在"拒绝，删除 Server 后的悬空授权若处理不当会让整份配置无法保存（同 R28 OBS-1 性质），见 OQ-R29-09。
